**macOS 向けの、無料・オープンソースの CleanMyMac 代替。**

`node_modules`、Xcode の `DerivedData`、Docker のボリューム、アプリのキャッシュ、アンインストール
の残骸を片づける SwiftUI ネイティブのディスククリーナーです。そして**本当の意味では何も削除しません**
—— 削除はすべてゴミ箱行きで、*あなた* がゴミ箱を空にするまで取り消せます。Electron なし、Python の
サイドカーなし、ローカルサーバーなし、テレメトリなし、サブスクリプションなし。UI は 10 言語。
DMG は約 5 MB で、Apple Silicon と Intel の両方を 1 ファイルに収めています。

## クイックスタート

このページ冒頭の GIF は、この順番をそのまま再生しています：

1. **空間総覧**を開く —— ボリューム全体を走査し、結果を 1 本のリングとして描きます。リングの隣が台帳です。
2. 台帳の任意の行をクリック —— その行の下にあるフォルダがその場で展開し、リングは小さな参照ダイヤルに
   引きます。
3. 丸ごと動かせる弧を**2 回**クリック：1 回目で武装、2 回目でゴミ箱へ。*元に戻す*で復帰し、ゴミ箱を
   空にするのは最後まで Finder の仕事です。

## AIエージェント向け

直販ビルドには `diskwise` CLI が同梱され（App Store 版にはありません）、それがそのまま
[Model Context Protocol](https://modelcontextprotocol.io) サーバーにもなります —— Claude Code、Cursor、Codex、Qoder、
OpenCode、Zed、ZCode、Claude Desktop のどれでも、ディスク領域の回収を任せられます。`rm -rf` はできません：
削除の経路は「知っているものだけをゴミ箱へ移す」一本道で、すべての操作は取り消せ、リスクのある場所には
そもそも手が届きません。

Claude Code なら、ターミナルで 1 行だけ：

```sh
claude mcp add diskwise -- "/Applications/DiskWise.app/Contents/MacOS/diskwise" mcp
```

あとはエージェントに*「この Mac で掃除する価値のあるところを見て」*と聞くだけ —— 走査し、計画を起こし、
要約を見せて、あなたが同意してから初めて動きます。上の 8 クライアントは一行ずつ動作確認済み。
ローカルの stdio MCP サーバーをホストできるクライアントなら、同じ 2 つの値 —— このバイナリのパスと
`mcp` 引数 —— で繋がります。繋がらないとしたら、それはクライアント側の問題です：issue と PR を歓迎します。
残り 7 クライアントの設定スニペットと安全モデルの詳細は [docs/AGENTS-CLI.md](docs/AGENTS-CLI.md)。

## なぜ作ったのか

ディスククリーナーは、役に立つことを言う前にまずあなたのマシンを大量に読まなければなりません。同種の
製品の多くはクローズドソースで、常駐デーモンを抱え、`rm -rf` を売り文句にしています。

DiskWise は逆を行きます：

| | DiskWise |
|---|---|
| 削除の経路 | **1 つだけ** —— `FileManager.trashItem`。すべてゴミ箱に入ります。 |
| 取り消し | あり。操作単位で、セッション中はいつでも。 |
| 保護パス | ホームディレクトリ自体、`~/Library` などは丸ごと削除できません。 |
| ゴミ箱を空にする | 実行するのは常に **Finder** で、このアプリではありません。直接版：アプリが Finder に依頼し、Finder がもう一度確認します。App Store 版：サンドボックスがそのイベントを握りつぶします（実測した挙動で、許可ダイアログすら出ません）—— そこで同じボタンがゴミ箱ウィンドウを開き、⌘⇧⌫ を押します。 |
| Docker イメージ | 読み取り専用。仮想ディスクにはイメージ単位のパスがないので、アプリは削除するふりをせず場所を指し示します。 |
| ネットワーク | なし。アップデータも解析も広告もありません。 |
| 価格 | 無料。このビルドでは全機能と 6 種類のスキンが解放済みです。 |
| 動作形態 | `.app` ひとつ。Python なし、ポートなし、デーモンなし。 |

キャッシュ一覧は、説明できる項目には説明を書いています —— これは何か、消したらどうなるか、どう戻る
のか。私たちは本当に理解している項目にしかこの文章を書かないので、書いてある行とない行があります。
WeChat、DingTalk、WeCom が入っているのは、多くのマシンでこの 3 つだけで数十 GB を占めるからです。

対象は、開発者が数年使ったマシンです —— `node_modules`、Docker のボリューム、Xcode の `DerivedData`、
そして十数 GB のキャッシュが静かに居座っているようなマシンです。

## できること

**容量を把握する**

- **空間総覧** —— ボリュームを 1 本のリングとして描きます。1 つの区画はこの走査で実際に測れたバイト数
  で、区画を足すとディスク全体になります（上位フォルダ ＋ その他集計済み ＋ 未測定 ＋ パージ可能 ＋ 空き）。
  - 光の帯は、いま測り終えた境界にちょうど止まります。
  - 丸ごと動かせる区画は 2 回タップ：1 回目で武装、2 回目でゴミ箱へ送られ、3 秒放置すると自分で解除
    されます。
  - 一覧は 1 つだけ、リングの隣の台帳です。行を開くとその場で内訳が展開します —— その行の下の
    フォルダ、*その他集計済み* の後ろにある場所、*未測定* の後ろにあるボリューム。
  - 行を開いている間、リングは小さな参照ダイヤルに引き、*Finder で表示* と *掘り下げる* がその行に
    載ります。
- **ディスク全体の走査** —— 範囲を推測させる余地はありません。オープンソース版はボリューム全体を歩きます
  （ホワイトリストのシステムルートも、他のユーザーのホームも含みます）。サンドボックス版の Mac App
  Store ビルドは、与えられた権限で届く範囲すべてを歩き、その境界を画面に書きます。
  - どちらでも対象はボリューム全体で、ホームフォルダの整った隅だけではありません。
- **測れなかった場所を名指しするカバレッジ行** —— 総覧は、使用中の容量のうち実際に測れたのはどれだけか
  を表示し、残りが誰の領域かを挙げます：システムボリューム、管理者しか読めないフォルダ、フルディスク
  アクセスで止まっているフォルダ。
  - *アクセスを許可* ボタンは、保護されたファイルを実際に読もうとして権限が本当に足りないと分かったとき
    だけ現れます。すでに許可済みのマシンが二度せかされることはありません。
  - 数値はすべて 10 進なので、Finder や「この Mac について」とバイト単位で一致します。
- **「その他集計済み」は足し算が合う** —— その行を開くと弧の後ろにある場所がすべて列挙され、最後の行が
  合計を内訳つきで書き出します（列挙した行 ＋ 100 MB の下限に収まったもの）。「100 GB 以上、信じてくれ」
  は説明にならないからです。
- **大きいファイル** —— 同じルート群を横断して上位 N 件。開発ディレクトリは除外できます。
- **長く触っていないもの** —— 同じルート群で、N 日間開いていないファイル。
- **重複ファイル** —— サイズ → 部分ハッシュ → 完全ハッシュ、でグループ化し、各グループの最新の 1 つを
  ロックして、唯一のコピーを消してしまう事故を防ぎます。
  - venv / site-packages / DerivedData の中にあるコピーは比較に入れず、別のリストに分けます。1 つ消すと
    その環境が 1 ピース欠けるからです。

**開発マシン向け**

- **node_modules** —— プロジェクト単位でまとめて走査するので、「この 3 つの checkout で 4.7 GB」と
  分かります。
- **Docker 使用量** —— 実際に入っているコンテナランタイム（Docker Desktop、OrbStack、Podman、colima）
  ごとに 1 行、その仮想ディスクがこのディスク上で占めている量を測り、エンジン自身が申告する数字を下に
  並べます。読み取り専用で、どこを削るべきかを指し示すだけで、代わりに消したりはしません。

**掃除する**

- **アプリキャッシュ** —— 手入れされた知識ベース（システムキャッシュ、クラッシュダンプ、WeChat /
  DingTalk / WeCom / QQ など）。各項目が *これは何か*、*消したらどうなるか*、*どう戻すか* を説明し、
  削除したときに何を失うかを示すバッジ（安全 / 再取得可 / データ消失）が付きます。
- **開発キャッシュ** —— 同じ知識ベースの別半分、こうしたマシンが実際にディスクを埋めるツール群：
  Homebrew、npm / pnpm / yarn、Maven、Gradle、conda、uv、cargo、Ollama のモデル、Xcode のアーカイブ、
  DerivedData、そしてシミュレータの各デバイスを 1 台ずつ。
- **アンインストール残骸** —— すでに消したアプリが残したデータを、いま入っているすべてのアプリの
  bundle id と突き合わせて見つけます。消しすぎるより、報告し損ねる側に倒します。
- **ゴミ箱** —— セッションの統計、取り消しスタック、そして *空にする* ボタン：サンドボックス外では
  Finder に空にしてもらい、App Store 版ではゴミ箱ウィンドウを開いて ⌘⇧⌫ を押します。

**見た目を変える**

- **スキン** —— 6 種類。面白いのはこれが色替えではないことです。1 つ 1 つが書体、角丸、浮き方、動きの
  質、グラフの配色を変えます。Morning Fog、Graphite、Mint、Polar Night、Aurora Glass、Ink & Paper ——
  6 つとも同梱です。
- **スキンはコードではなくデータ** —— 6 つとも
  [`Sources/DiskCleaner/Resources/skins.json`](Sources/DiskCleaner/Resources/skins.json) という 1 つの
  ファイルにあり、そのファイルが自分のフィールドを説明しています。7 つ目は JSON オブジェクト 1 つ分：
  GitHub のブラウザ上でそのファイルを編集して PR を出せば済み、Xcode もビルドも Swift も要りません。

## インストール

### Mac App Store

[DiskWise: Storage Cleaner](https://apps.apple.com/app/id6813265402) —— macOS 13+、無料。入れてすぐ
使い始められ、以降のバージョンはストアが引き継ぎます。

ストアが引き継ぐ各バージョンは先に Apple の審査を通過する必要があるため、GitHub Release より少し
遅れて届きます。出たてのバージョンをすぐ使いたい場合は、下の Homebrew か DMG を使ってください。

### Homebrew（コマンド 1 つ）

```sh
brew install --cask dreamofxm/diskwise/diskwise
```

サードパーティの tap からこれが通るのは完全修飾名のおかげです。Homebrew 6 以降、非公式 tap は既定で
信頼されず、完全修飾名で入れるとこの cask だけが信頼されます。短い名前を使いたい場合：

```sh
brew tap DreamOfXM/diskwise
brew trust --cask dreamofxm/diskwise/diskwise
brew install --cask diskwise
```

tap の詳細と、固定しているチェックサムの更新方法は
[DreamOfXM/homebrew-diskwise](https://github.com/DreamOfXM/homebrew-diskwise) にあります。

Homebrew が入れるのは Releases ページにあるのと同じファイルです。v1.7 以降は Developer ID 証明書で
署名し Apple に公証されているので、Gatekeeper に止められずダブルクリックで開けます。v1.7 より前の
ビルドは ad-hoc 署名のため初回起動を一度止められます。macOS が止めたら **システム設定 →
プライバシーとセキュリティ → このまま開く** で許可してください（macOS 13–14 では右クリック → 開く
でも同じです）。**Mac App Store** から入れればこの手順は不要です。

### DMG

1. [Releases](https://github.com/DreamOfXM/diskwise/releases) から
   `DiskWise-<バージョン>[-universal].dmg` をダウンロードします。
2. 開いて **DiskWise.app** を *アプリケーション* にドラッグします。
3. ダブルクリックすれば開きます。v1.7 以降は署名と公証が済んでいるので macOS は止めません。v1.7
   より前のビルドは初回に一度止められ、**システム設定 → プライバシーとセキュリティ → このまま開く**
   で許可すれば、以降は普通に開きます（macOS 13–14 では右クリック → 開く が使えます。Sequoia はこの
   近道を廃止しました）。

`ARCH=universal` で作ったリリースは `…-universal.dmg` という名前で、Apple Silicon と Intel の両方の
スライスを 1 ファイルに含みます。Apple Silicon のみのものは `DiskWise-<バージョン>.dmg` です。チェック
サムは各アセットの隣に公開され、cask も同じ SHA-256 を固定しています。

## ソースからビルドする

必要なのは Xcode コマンドラインツールだけです。**完全な Xcode は不要**です。

```bash
swift build                    # デバッグ
swift run SelfTest             # 全緑がリリースの前提条件
swift run DiskCleaner          # アプリを起動
bash build_app/build.sh        # 翻訳チェック → ビルド → 自己テスト → .app → 署名 → dist/*.dmg + SHA256
```

3 つのゲートのどれかが失敗すると `build.sh` はパッケージを作りません：翻訳の欠落、自己テストの失敗、
リソースの取り込み漏れです。翻訳ゲートは Swift のソースと `skins.json` 自体を解析するので、訳が
足りない場合だけでなく、`L(…)` で包み忘れたユーザー可視文字列も捕まえます —— ある言語が半分だけ訳された
状態で静かに出荷されることはありません。

コントリビュートするなら、まず [CONTRIBUTING.md](CONTRIBUTING.md)、次に
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) と [docs/DESIGN.md](docs/DESIGN.md) を読んでください。
どちらにも、高くついた末に決まったルールが書かれています。Swift を一切触らない PR が 3 種類あります：
[キャッシュ知識ベース](CONTRIBUTING.md#the-easiest-useful-contribution-cache-knowledge-base)への 1 項目、
[スキン](CONTRIBUTING.md#skins)、そして[翻訳](CONTRIBUTING.md#translations)です。

## よくある質問

**これは CleanMyMac の代替ですか？**
同じ領域をカバーするという意味では —— キャッシュ、大きいファイル、重複ファイル、アンインストール残骸、
Docker 使用量 —— ソースはこのページにあり、サブスクリプションもありません。一方でスイートより
*わざと* 少なく作っています：マルウェアスキャンなし、VPN なし、メールの掃除なし、「高速化」なし。
それらは別の製品で、別のリスクだからです。

**本当に必要なものを消してしまいませんか？**
削除したものはすべてゴミ箱に入り、セッション中は取り消しスタックが残ります。ホームディレクトリ自体と
`~/Library` は丸ごとは削除できません。ゴミ箱を空にするのは Finder の仕事なので、容量が本当に解放される
前に macOS がもう一度確認します。

**`node_modules` や `DerivedData`、キャッシュを消しても大丈夫ですか？**
`node_modules` は `npm install` で、`DerivedData` は次の Xcode ビルドで、キャッシュはそれを書いたツール
の次の実行で戻ります。DiskWise はそれを知っている前提にせず、項目ごとに書いています —— キャッシュの各行が
これは何か、消したらどうなるか、どう戻すかを述べます。

**どこかにデータを送りますか？**
いいえ。アップデータも解析もアカウントも広告もありません —— アプリにはネットワークアクセスが一切
ありません。フィードバックが GitHub かメール経由なのもそれが理由です。

**WeChat / DingTalk / WeCom のキャッシュは対応していますか？**
対応しています。キャッシュ知識ベースに入っています。中国の開発者の Mac ではこれらが単体で最大の容量
消費者になることが多いからです。簡体字と繁体字の中国語がどちらも一等公民なのも、英語 UI に後付けした
翻訳ではないからです。

**Intel Mac は？**
v1.3 以降、公開している DMG はすべて `ARCH=universal` で作られ、arm64 と x86_64 の両スライスを 1
ファイルに含むので、同じダウンロードが Apple Silicon でも Intel でも動きます。v1.3 より前のリリースは
arm64 のみ（`DiskWise-<バージョン>.dmg`、名前に `-universal` なし）なので、それらのバージョンで Intel を
使う場合はソースからビルドしてください（1 分で終わり、Xcode は不要です）。`bash build_app/build.sh` は
今も既定で Apple Silicon のみで、両方得るには `ARCH=universal` を渡します。

**なぜ初回起動で macOS が警告を出すのですか？**
v1.7 以降は出しません: v1.7 以降の公開物はすべて Developer ID 証明書で署名し Apple に公証済みなので、
Gatekeeper をそのまま通ります。それ以前の ad-hoc ビルドは初回だけ止められます:
**システム設定 → プライバシーとセキュリティ → このまま開く** で許可すれば以降は普通に起動します。
macOS 13–14 では右クリック → 開く でも同じです（Sequoia はこの近道を廃止しました）。App Store 版は
止められません。

## 既知の制限

- **システム領域は数えるだけで、掃除はしません。** `/Library`、`/opt`、`/private` 配下の行には
  *システム領域* バッジが付き、チェックボックスはロックされます。管理者しか書けないか、Homebrew / Xcode
  の持ち物で、それぞれの掃除コマンドのほうが上手くやるからです。
- **大きな `node_modules` の走査は遅く**、まだ結果をストリーミングしません。
- **すべての残骸を見つけるわけではありません。** 残骸検出は意図的に保守的です。

|---|---|

次の人に届く最も現実的な方法です。このプロジェクトには広告費がなく、GitHub の検索と awesome リストからの
流入が「誰の目に入るか」をそのまま決めます。
